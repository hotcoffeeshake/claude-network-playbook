# 当前保护机制与明确边界

基线日期：2026-10-02。这里描述“已经配置或提供的方法”，不把历史测试视为新机器验收。

## 四层机制

1. **固定目的出口**：Claude 第一方域名及两个检测站绑定 `US-FIXED`。组内仅有一个固定美国 TLS 节点，不放 DIRECT、自动测速组或其他国家节点。正常配置模式下，更换首页其他服务的默认节点不应改变该组；实际仍须检查请求日志和出口。
2. **不自动直连回退**：禁用节点自动回退；不支持的 UDP 使用 REJECT。固定节点故障时这些规则没有另一个备用出口。此机制依赖 Shadowrocket 正在接管流量、规则未被覆盖；不是独立系统防火墙。
3. **应用直连限制**：LuLu 对 Claude 主程序、桌面 Code 实际执行路径分别限制外部直连，Code 显式使用本机 HTTP 代理。规则须在新机器验证。回环通信会旁路，因此其他本机转发器仍是边界；浏览器、Flova、外部工具与所有子进程不会自动继承保护。
4. **手动启动前出口核对**：仓库脚本向两个检测站发无凭据请求，结果须等于本地指定的固定公网 IPv4。失败退出非零；它不会启动、终止或修改任何应用。

## 与“跳 IP 自动停止”有什么差别

本仓库没有运行中持续监测，也没有检测到 IP 改变后自动终止 Claude、关闭本地代理或阻断已建立连接的程序。启动前通过，只代表检查时刻通过。LuLu限制的是进程能否直连，不能判断一个被允许访问的本地代理后来使用哪个公网 IP。

同一静态公网 IP 下由 WireGuard 改成 Trojan，是传输方式变化；是否换出口须实际测量，不能仅凭节点名称或协议判断。VPS 静态地址被解绑、更换上游出口、配置组被编辑或 VPN 被关闭均需重新验收。

未来若要实现运行中锁定，必须单独交付阻断执行机制、崩溃后保持阻断、重启行为和故障注入测试。单纯定时查询后杀进程存在检测窗口，不能称为零泄漏。此版本不宣称已实现这些能力。

## 本机遗留与新机器区别

旧 Mac 的独立 CLI 启动器曾在启动前执行全量本机检查，再调用专用 Node。旧检查器仍引用原 WireGuard 节点名称和本机路径，尚未迁移成当前 TLS 节点的通用实现。不要复制它，也不要删除校验来“修复”拒绝启动。仓库的 `check_exit.py` 只是可移植的出口测试，不能替代它。

当前 Mac 的单成员 US-FIXED 路由已核对；LuLu目录探针的历史结果不代表新安装版本、所有进程和真实 Code 会话均已验收。手机不继承 macOS LuLu 规则。

## 明确不覆盖

- 网页 Claude 所在浏览器、其他 IDE、自带 CLI、远程/云端会话，除非另行配置并测试。
- Claude 调用的 Flova、Bilibili 等外部工具；按本手册，它们允许国内流量。
- 账号地区、订阅、使用行为和平台封禁判断；网络配置不构成不会封号的保证。
- 国外物理网络下的“中国 IP”：DIRECT 只表示当前网络直连，不会把国外网络变成中国出口。
