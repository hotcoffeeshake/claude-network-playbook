# 完整操作手册

本文保存操作指示，不包含本人的服务器参数。所有 `<...>` 在本地替换；真实值不要提交到仓库。先阅读验证范围，再实施到新设备。

## 1. 建立自有服务器

1. 在供应商官方控制台注册，选美国区域、Ubuntu LTS、小规格实例，并确认月费、流量计费及免费期；付款由用户完成。
2. 创建静态公网 IPv4 并绑定实例。记录真实地址到本地私密笔记，不写入仓库。
3. 使用供应商生成的 SSH 密钥连接，私钥权限设为600；服务器 SSH 仅保留必要来源。云防火墙允许 WireGuard 的 UDP51820，关闭不需要的80等端口。不要误删当前管理入口。
4. 在服务器安装 WireGuard，开启 IPv4 转发；给wg0分配私有隧道网段；配置隧道到实际公网网卡的转发和MASQUERADE。网卡名称用 `ip route show default` 检查，不能照抄别人的网卡名。
5. 服务器、电脑、手机分别在本地生成密钥。电脑与手机各使用一个peer及唯一隧道地址。服务器端每个peer的AllowedIPs只填写该peer地址/32，客户端使用0.0.0.0/0与::/0，服务器不提供IPv6转发，使IPv6外连失败；在每个客户端实测接管效果。
6. 通过systemd启用wg-quick@wg0；检查active/enabled、监听端口及最近握手。避免把完整wg配置打印到日志。
7. 保存修改前配置及安全回滚通道。不要在唯一管理通道也依赖该隧道时直接停掉wg0。

可用于空白Ubuntu服务器的基础命令（不是一键部署）：

```sh
sudo apt-get update
sudo apt-get install wireguard
ip route show default
sudo install -m 600 /path/to/reviewed-wg0.conf /etc/wireguard/wg0.conf
# 配好转发、NAT、云防火墙后才启动
sudo systemctl enable --now wg-quick@wg0
sudo systemctl is-active wg-quick@wg0
sudo systemctl is-enabled wg-quick@wg0
sudo wg show wg0 latest-handshakes
```

服务端模板见 `templates/wg-server.conf.example`，示例不会自动执行防火墙配置。必须替换网卡、密钥和peer参数再审阅。

## 2. Shadowrocket 导入与分流

1. 导入电脑专用WireGuard配置，节点命名如 `MY-US-FIXED`；手机用不同peer。
2. 全局路由选择“配置”，默认节点选固定美国节点，关闭自动回退。
3. 将 `templates/shadowrocket-rules.conf.example` 的域名规则加入现有规则顶部，保留原有GEOIP和FINAL；General逐键合并。PROXY表示当前选中的节点，因此使用期间不要切换节点。
4. Claude第一方域名与两个出口检测域名走PROXY；Flova/Bilibili走DIRECT；保留既有国内规则与FINAL策略。
5. 电脑本地HTTP代理为127.0.0.1:1082。用 `scutil --proxy` 核对实际端口；不把监听开放给局域网。
6. 先备份现有配置。不要整体导入别人完整配置而覆盖自己的订阅或规则。

## 3. 修复 DNS

在“配置 → 当前配置 → 通用”编辑DNS覆写与备用DNS：

```ini
dns-server = https://1.1.1.1/dns-query#proxy
fallback-dns-server = https://1.0.0.1/dns-query#proxy
dns-direct-system = false
dns-direct-fallback-proxy = false
```

删除主备列表中的system及旧明文服务器，点击更新配置，再重新进入页面核对。本机UI编辑保存曾留下暂时旧条目；重新进入并再次更新后落盘列表仅保留最终条目。因此必须核对重复项，不能只读取最后一个同名键。

本次版本以fallback-dns-server列表管理备用解析；不要凭其他版本教程添加不存在的开关。主备均使用同一个厂商，厂商故障可能同时影响两者；失败时先排查，不自动改成system或更换出口。

打开 https://browserleaks.com/dns ，等待完整结果。目标是没有国内运营商解析、当前检测得到预期美国解析节点。DNS的解析服务器IP与网页出口IP可以不同。Cloudflare节点地理数据库标签只是辅助，需要结合实际路由判断。

## 4. 桌面 Code 的显式代理

备份 `~/.claude/settings.json`，将模板 `templates/claude-env.json` 的env字段**合并**进去，保留原有plugins/hooks等字段。不要用模板覆盖整个文件。

- HTTP_PROXY、HTTPS_PROXY及小写版本均指向本机HTTP代理。
- NO_PROXY与小写版本仅包括localhost、127.0.0.1、::1。
- CLAUDE_CODE_PROXY_RESOLVES_HOSTS=1。
- 保持证书校验，不加关闭TLS验证的环境变量。

设置会在进程启动时读取；旧会话需正常退出后重新打开。桌面本地Code会话可以读取项目设置，因此还要检查当前项目 `.claude/settings.json`、`.claude/settings.local.json` 和组织managed settings是否覆盖代理。

官方说明：https://code.claude.com/docs/en/network-config

## 5. LuLu 应用级直连保护

分别创建下列目录范围：

- `/Applications/Claude.app/*`
- `$HOME/Library/Application Support/Claude/claude-code/*`（UI中填实际展开的绝对路径）
- 若安装CLI保护入口，再增加专用运行时目录。

每个范围设置两条永久规则：

| 动作 | 远程地址 | 端口 | 正则 |
|---|---|---|---|
| 阻止 | `^.*$` | 任意 | 开启 |
| 允许 | `127.0.0.1` | `1082` | 关闭 |

本机LuLu版本3.1.5已用实际连接验证上述目录优先级。它阻止外部直连，系统回环通信会旁路，不应描述为“只有1082可访问”。保留LuLu网络扩展启用，关闭被动模式，不添加全局放行。

桌面Code下载位置在用户目录，与主应用不同。升级后检查实际执行文件仍在范围内、可执行且签名通过：

```sh
codesign --verify --deep --strict '/path/to/downloaded/claude.app'
```

不要修改签名应用包；验收可用目录下独立临时探针测试，完成后删除测试文件。

## 6. 终端 CLI 与 Cursor

终端npm版可能使用系统共享Node。不要直接给共享Node新增全局阻断规则，以免影响其他开发工具。

本机采用：独立Node副本 → 专用目录LuLu规则 → PATH前置的claude启动入口。入口先检查，再强制HTTP代理，清理ALL_PROXY和NODE_OPTIONS，调用原npm CLI。运行时/CLI/入口记录哈希；更新后重新验收。后台、远程、云端功能未按此前台入口验收，不视为自动覆盖。

这部分是操作说明，仓库没有直接复制含设备参数的现有包装器。新机器需重新确定CLI安装方式，不能机械套用旧版本路径。

此前Cursor连接重置处理采用 `http.proxySupport=off`，由现有TUN承担路由。它不等于Cursor也得到本手册的Claude专用防火墙保护；网络诊断、模型列表、聊天与Agent需分别测试。

## 7. iPhone 导入

1. 服务端添加手机独立peer，不复用电脑私钥或隧道地址。
2. 手机Shadowrocket扫描自己生成的WireGuard二维码，或通过可信本地传输导入配置。
3. 二维码含完整连接凭据，不上传GitHub、不发公开聊天、不交给在线二维码服务。
4. 导入无凭据的分流规则；在手机上同步第3节DNS设置，选择自己的美国节点、配置模式、关闭回退。
5. 分别测手机Safari出口、DNS、WebRTC；再判断原生App。电脑的LuLu规则不保护手机，手机关闭VPN后仍可能直连。

本轮只远程修改了电脑；手机DNS还需用户同步。原有手机连接由用户确认成功，未在本轮完成手机出口测量。

## 8. 验收与日常使用

- 配置验收：LuLu启用、两套桌面目录、代理环境、主备DNS各唯一且无system、固定节点、回退关闭。
- 无账号网络验收：两个IP站输出同一预期静态地址；IPv4/IPv6外部直连失败；代理成功；错误代理端口失败；本地IPC可用。
- 浏览器验收：DNS完整结果、WebRTC结果。不要申请摄像头、麦克风或地理位置权限来完成普通检测。
- 国内服务验收：Flova主页返回成功，国内出口检测站保持国内；上传/CDN域名另外核对。
- 真实Code验收：在用户自己的本地会话中看 `/status` 的Proxy，再核对连接日志。无账号测试不能替代这一步。
- 运行中不要切节点；开机后先启动防护、连固定节点、检查通过再用Code。

仓库的 `scripts/check_exit.py --expected-ip <实际地址>` 仅做无账号出口检查，不替代本机完整防火墙检查器；它不写入真实地址，也不会启动Claude。

## 9. 故障与恢复

检测失败先退出相关会话。核对节点/规则/DNS/进程，不通过改IP或关闭防火墙“消除报错”。恢复配置前保存当前版本；只撤销本次修改项，避免覆盖后来新规则。

DNS回滚可从本地备份恢复原值，但恢复system会重新引入原来的解析路径。CLI回滚为移开PATH前置入口并移除专用目录规则；桌面规则单独处理。不要整份覆盖LuLu规则库。

原始配置、数据库、日志、账号导出、密钥与二维码保存在本地受限目录，不提交。上传使用全新目录、明确文件列表和.gitignore；提交后检查GitHub visibility为PRIVATE及远端文件清单。
