# 完整操作手册

本文保存操作指示，不包含本人的服务器参数。所有 `<...>` 在本地替换；真实值不要提交到仓库。先阅读验证范围，再实施到新设备。

## 1. 当前主通道：固定美国 VPS + Trojan/TCP/TLS

2026-10-02 版本以已有的可信 TLS 节点为主，WireGuard 的 `wg-*.conf.example` 仅供历史方案参考。另一台 Mac 接现有服务器时不需要再建一台 VPS，参照[迁移步骤](另一台Mac部署.md)取得该设备独立凭据。

从零新建服务端属于另一项部署工作，本仓库没有一键脚本。需要固定公网 IPv4、受信任且名称匹配的证书、Trojan服务、独立设备凭据、持久化启动及证书续期。官方字段与版本迁移以 [sing-box Trojan](https://sing-box.sagernet.org/configuration/inbound/trojan/) 和 [TLS 文档](https://sing-box.sagernet.org/configuration/shared/tls/) 为准。不能用关闭证书验证代替签发和续期。

服务端 TCP 443 及独立 SSH 管理入口应按需开放；证书验证若使用 HTTP-01，TCP80 的开放条件取决于签发方式，不要沿用旧 WireGuard 教程关闭它。设置最小运行权限、禁止代理访问实例元数据/私网/回环目标；先验证所用 sing-box 版本配置，再加载。

现有服务器采用证书定期续期、部署后 TLS 健康检查及失败回滚。仓库只记录这些运维要求，未附服务器部署脚本。新服务器必须独立验证续期定时器、证书有效期及回滚，不得因为有公网 IP 就判定全部就绪。

## 2. 固定组与国内分流

将 [Shadowrocket 合并模板](../templates/shadowrocket-rules.conf.example) 按段合并到现有配置。替换 VPS 地址占位符并创建真实的 `MY-US-TLS-FIXED` 节点。`US-FIXED` 只含该一个节点，Claude 和检测站明确绑定该组，不再使用随首页选项改变的通用 PROXY。

全局路由用“配置”，默认节点选固定节点并关闭自动回退。规则优先级必须核对：固定组规则在宽泛域名、规则集和 GEOIP/FINAL 前，VPS 自身端点排除在前；保留原 Apple Relay 特例。分流模式只是路由机制，代理关闭后的应用直连须依赖经验证的防火墙。

完整的国内服务和 DNS 清单见[这里](国内流量与DNS清单.md)。DIRECT 的出口由所在网络决定，不等于永远中国 IP。

## 3. DNS 默认代理 + 国内业务例外

```ini
dns-server = https://1.1.1.1/dns-query#proxy
fallback-dns-server = https://1.0.0.1/dns-query#proxy
dns-direct-system = false
dns-direct-fallback-proxy = false
udp-policy-not-supported-behaviour = REJECT
ipv6 = true
prefer-ipv6 = false
```

为[模板 Host 段](../templates/shadowrocket-rules.conf.example)列出的国内业务使用 `server:223.5.5.5`，避免国内直连却拿到不适用的海外 CDN 地址。不要为 Claude 添加国内 DNS 例外，也不要固定某次解析得到的短期 CDN IP。

各键合并后检查重复项；保存和运行中的 DNS 日志都需验证。通用 DNS/WebRTC 检测只是辅助，业务专属国内 DNS 是有意设置的例外，不能声称本机所有 DNS 都在美国。默认 DoH 的 #proxy 路径还受首页节点影响，使用期间保持固定。

## 4. 桌面 Code 的显式代理

备份 `~/.claude/settings.json`，将模板 `templates/claude-env.json` 的env字段**合并**进去，保留原有plugins/hooks等字段。不要用模板覆盖整个文件。

- HTTP_PROXY、HTTPS_PROXY及小写版本均指向本机HTTP代理。
- NO_PROXY与小写版本仅包括localhost、127.0.0.1、::1。
- CLAUDE_CODE_PROXY_RESOLVES_HOSTS=1。
- 保持证书校验，不加关闭TLS验证的环境变量。

设置会在进程启动时读取；旧会话需正常退出后重新打开。桌面本地Code会话可以读取项目设置，因此还要检查当前项目 `.claude/settings.json`、`.claude/settings.local.json` 和组织managed settings是否覆盖代理。

官方说明：https://code.claude.com/docs/en/network-config

## 5. LuLu 应用级直连保护

分别创建下列目录范围：

- `/Applications/Claude.app/*`
- `$HOME/Library/Application Support/Claude/claude-code/*`（UI中填实际展开的绝对路径）
- 若安装CLI保护入口，再增加专用运行时目录。

每个范围设置两条永久规则：

| 动作 | 远程地址 | 端口 | 正则 |
|---|---|---|---|
| 阻止 | `^.*$` | 任意 | 开启 |
| 允许 | `127.0.0.1` | `1082` | 关闭 |

历史本机LuLu版本3.1.5曾用实际连接验证上述目录优先级；新机器及新版本必须重做测试。它阻止外部直连，系统回环通信会旁路，不应描述为“只有1082可访问”。保留LuLu网络扩展启用，关闭被动模式，不添加全局放行。

桌面Code下载位置在用户目录，与主应用不同。升级后检查实际执行文件仍在范围内、可执行且签名通过：

```sh
codesign --verify --deep --strict '/path/to/downloaded/claude.app'
```

不要修改签名应用包；验收可用目录下独立临时探针测试，完成后删除测试文件。

## 6. 终端 CLI 与 Cursor

终端npm版可能使用系统共享Node。不要直接给共享Node新增全局阻断规则，以免影响其他开发工具。

历史本机采用（检查器尚未适配当前TLS节点，不可直接迁移）：独立Node副本 → 专用目录LuLu规则 → PATH前置的claude启动入口。入口先检查，再强制HTTP代理，清理ALL_PROXY和NODE_OPTIONS，调用原npm CLI。运行时/CLI/入口记录哈希；更新后重新验收。仓库不提供该启动器的通用安装版本。后台、远程、云端功能未按此前台入口验收，不视为自动覆盖。

这部分是操作说明，仓库没有直接复制含设备参数的现有包装器。新机器需重新确定CLI安装方式，不能机械套用旧版本路径。

此前Cursor连接重置处理采用 `http.proxySupport=off`，由现有TUN承担路由。它不等于Cursor也得到本手册的Claude专用防火墙保护；网络诊断、模型列表、聊天与Agent需分别测试。

## 7. iPhone 导入

1. 当前 Trojan 服务端为手机设置独立凭据；若另用 WireGuard，则用独立peer、密钥和隧道地址。
2. 手机Shadowrocket扫描该手机专用 Trojan 节点二维码，或通过可信本地传输导入。WireGuard旧二维码不能当作TLS节点使用。
3. 二维码含完整连接凭据，不上传GitHub、不发公开聊天、不交给在线二维码服务。
4. 导入无凭据的分流规则；在手机上同步第3节DNS设置，选择自己的美国节点、配置模式、关闭回退。
5. 分别测手机Safari出口、DNS、WebRTC；再判断原生App。电脑的LuLu规则不保护手机，手机关闭VPN后仍可能直连。

此前已提供手机专用TLS节点二维码，并从电脑验证其凭据和固定出口；手机自身的分流、DNS及断线行为仍需在手机上独立验收。扫码不会同步电脑配置。

## 8. 验收与日常使用

- 配置验收：LuLu启用、两套桌面目录、代理环境、主备DNS各唯一且无system、固定节点、回退关闭。
- 无账号网络验收：两个IP站输出同一预期静态地址；IPv4/IPv6外部直连失败；代理成功；错误代理端口失败；本地IPC可用。
- 浏览器验收：DNS完整结果、WebRTC结果。不要申请摄像头、麦克风或地理位置权限来完成普通检测。
- 国内服务验收：Flova主页返回成功，国内出口检测站保持国内；上传/CDN域名另外核对。
- 真实Code验收：在用户自己的本地会话中看 `/status` 的Proxy，再核对连接日志。无账号测试不能替代这一步。
- 运行中不要切节点；开机后先启动防护、连固定节点、检查通过再用Code。

仓库的 `python3 scripts/check_exit.py --expected-ip <实际地址>` 仅做无账号出口检查，不替代本机完整防火墙检查器；它不写入真实地址，也不会启动Claude。

## 9. 故障与恢复

检测失败先退出相关会话。核对节点/规则/DNS/进程，不通过改IP或关闭防火墙“消除报错”。恢复配置前保存当前版本；只撤销本次修改项，避免覆盖后来新规则。

DNS回滚可从本地备份恢复原值，但恢复system会重新引入原来的解析路径。CLI回滚为移开PATH前置入口并移除专用目录规则；桌面规则单独处理。不要整份覆盖LuLu规则库。

原始配置、数据库、日志、账号导出、密钥与二维码保存在本地受限目录，不提交。上传使用全新目录、明确文件列表和.gitignore；提交后检查GitHub visibility为PRIVATE及远端文件清单。
