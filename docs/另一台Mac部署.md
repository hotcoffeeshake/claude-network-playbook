# 另一台 Mac 部署与验收

版本：2026-10-02。目标：在另一台 Mac 重建当前的固定节点分流与应用直连限制。**不包含运行中 IP 改变自动断流。** 适用于你已有可用美国 TLS VPS 的情况；只有仓库、没有节点凭据时不能完成连接。

## 0. 必须先准备

- macOS 上的 Shadowrocket、LuLu、Python 3，以及准备使用的 Claude 客户端/CLI。通过各自官方渠道安装。
- 已核实的静态美国公网 IPv4、Trojan TCP 443 地址、可信证书及验证名称、为这台机器单独配置的凭据。
- 凭据由自己的服务器管理渠道提供，放在 Git 仓库外，文件权限 0600；不要把原电脑账号文件、QR、数据库或整个配置目录同步到新机器。
- 现有 Shadowrocket 与 Claude 设置备份，以及可以手动操作本机的回滚通道。

在中国网络部署时，DIRECT 才通常对应中国出口。如果新机器在国外，先重新确定国内服务的访问需求。

```sh
git clone https://github.com/hotcoffeeshake/claude-network-playbook.git
cd claude-network-playbook
python3 --version
```

本仓库公开可读，HTTPS 克隆不需要仓库成员权限；提交修改仍需相应授权。克隆后不会自动安装保护。

## 1. 先让固定节点独立可用

在 Shadowrocket 导入这台 Mac 的 Trojan 节点，命名 `MY-US-TLS-FIXED`。核对 TCP 443、证书验证开启、验证名称与证书 SAN 一致。IP 证书与域名证书的填法不同，不能凭模板关闭校验。不要复制 WireGuard 类型后只改节点名字。

不要复用手机二维码作为另一台电脑的正式身份；让服务器管理员添加独立凭据以便单独撤销。只有需要新建 VPS 时才另行部署服务端，见[操作手册](操作手册.md)。

## 2. 合并分流与 DNS

1. 在 Shadowrocket 备份当前配置。
2. 打开 `templates/shadowrocket-rules.conf.example`，将 `<VPS_IPV4>` 换成自己的静态 IPv4。此真实值只保存在本地，不提交。使用域名端点时还要为端点域名添加精确 DIRECT，避免连接递归。
3. General、Proxy Group、Host 分别逐项合并到现有同名段，不要制造重复段或重复键。
4. Rule 中先放本机代理端点排除，再放 Claude US-FIXED 规则、国内服务规则，全部位于宽泛规则和 GEOIP/FINAL 前面。检查已有模块、规则集或更靠前的规则是否覆盖。
5. `US-FIXED = select, MY-US-TLS-FIXED`：恰好一个已存在的真实节点，不允许 DIRECT、其他代理组或自动回退。
6. 全局路由选“配置”，首页默认节点也选该固定节点，关闭回退。默认 DoH 的 `#proxy` 使用当前代理路径，所以不要在使用 Claude 时随意更换首页默认节点。
7. 本地 HTTP 代理端口按实际值核对。模板使用 127.0.0.1:1082；若不同，统一修改检查命令和 Code 设置。不要为了导入规则开启局域网代理共享。
8. 保存后重开配置页核对实际生效内容。

```sh
scutil --proxy
python3 scripts/check_exit.py --expected-ip '替换为自己的静态公网IPv4' --proxy http://127.0.0.1:1082
```

**只有脚本退出码为 0 才继续。** 这是人工流程门槛，不是自动拦截器；它不会阻止你手动打开 Claude。

## 3. 配置 Code 与应用防火墙

先完全退出 Claude/Code。把 `templates/claude-env.json` 的 env 字段合并进用户 `~/.claude/settings.json`，不要覆盖插件、hooks 和其他设置。用户级 env 针对 Code，不代表 Claude 桌面所有网络组件或浏览器都遵循它。核对项目和组织设置没有覆盖代理。

依[操作手册第 5 节](操作手册.md#5-lulu-应用级直连保护)，给实际的 Claude 主应用和桌面 Code 执行目录建立 LuLu 规则。新版本安装路径必须现场确认；不是照抄原电脑路径。

终端 CLI 根据真实安装类型另行处理：原生独立可执行文件按实际路径配置；npm CLI 不能封锁共享 Node。需要专用运行时与受控启动器时须另外部署、审查和验收，本仓库没有该通用安装器。**未完成时终端 CLI 标记为未保护，不要在验收表勾选通过。**

LuLu安装完成不等于规则有效；其网络扩展需处于启用、非被动状态，且无优先级更高的放行。不要覆盖新机器整份防火墙数据库。

## 4. 在本机完成以下验收

测试先关闭真实账号会话，用与目标进程相同规则范围的无凭据探针；不改签名应用包。主应用若无法安全使用同范围探针，需用其真实连接日志和防火墙判定补验，不以 shell curl 代替。预先恢复方式要可用。

| 检查 | 通过条件 |
|---|---|
| 固定出口 | 两个站均与指定静态 IPv4 一致，规则日志命中 US-FIXED |
| 应用直连限制 | 每个受保护程序范围的外部 IPv4、IPv6 测试均被 LuLu 阻止；日志有对应进程证据 |
| 正常代理 | 同范围通过本机代理能连接；证书验证通过 |
| 错误代理端口 | 同范围使用不存在的端口失败，不能直接连成功 |
| 代理失效 | 用无账号探针停止本机代理后请求失败；恢复后仍是原 IP。必须在有本机操作能力时做，不停唯一远程管理链路 |
| 本地 IPC | Claude/Code 所需回环通信可用；不把回环旁路误写为仅1082放行 |
| 国内分流 | 逐个检查实际使用的 Flova/飞书/抖音/小红书/WorkBuddy 等请求与 DNS 日志；目录探针成功不代表所有第三方工具成功 |
| 真实 Code 会话 | 无账号测试通过后，再由用户打开本地会话，核对代理设置、实际模型请求及后台辅助进程 |
| 重启复验 | 重启后 LuLu启用，Shadowrocket使用正确配置与固定节点，重新执行出口检查 |

不能完成某一项就保留“未验收”，不能把这台机器标记为全部保护。运行中改 IP 的自动停止测试不在表内，因为本仓库尚无这个功能。

## 5. 国内应用与手机

国内域名清单和 DNS 例外见[清单](国内流量与DNS清单.md)。Flova、B站等外部工具按自己的域名路由，不自动继承 Claude 目录的 LuLu 限制。

iPhone 独立节点需另外配置。扫码只导入节点；不自动同步此分流模板、DNS 或 Mac 防火墙。手机的原生应用和断开 VPN 后行为独立验收。

## 6. 回滚和交接

只撤销此次新增的规则、DNS 键和 Code env 键，不覆盖其他配置。撤销 LuLu 规则会取消对应程序的直连防护，先退出相关程序再操作。

留在新机器本地的验收记录应包含：日期、软件版本、可执行路径、各项通过/失败、已完成/未覆盖范围。分享时删掉公网 IP、设备标识、账号和日志里的认证头。源码更新与本机已生效配置是两件事：git pull 不会自动部署。
