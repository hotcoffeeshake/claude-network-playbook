# 从三篇教程到一套能检查的 Claude 桌面 Code 网络方案

> 2026-10-02 更新：正文的最初测试属于历史记录；当前 TLS 主通道、固定 US-FIXED 分组、国内 DNS 例外及未实现的持续断流范围，以[保护边界](保护机制与边界.md)和[部署手册](另一台Mac部署.md)为准。

这次整理解决的是一个具体问题：电脑用 Claude 桌面版的 Code 页，手机偶尔连接同一台自有服务器，Flova、Bilibili 又需要国内访问。怎样让模型连接保持固定出口，同时知道哪些设置真正生效？

我把教程中的提醒逐项对应到实际操作。下面明确区分“作者提到什么”“本次做了什么”和“仍需要用户执行什么”。来源完整链接见[来源索引](来源.md)。

## 二、把“美国出口”做成能核对的连接路径

当前电脑链路是：桌面 Code → 本机 HTTP 代理 → Shadowrocket → Trojan/TCP/TLS → 自有美国服务器；最初使用的 WireGuard 已保留为历史方案。服务器使用静态公网地址，客户端只选这一条固定节点并关闭自动回退。

这样做的重点是减少节点切换。它没有把云服务器变成住宅宽带；固定地址、独享地址、住宅地址是不同属性。金融服务提示 VPN 时，也不能用一次出口测试代替它自己的准入检查。

Code 的代理地址写进用户级 settings.json，同时设置大小写 HTTP_PROXY、HTTPS_PROXY，避免某个小写变量覆盖大写变量。NO_PROXY 只列回环地址，保留桌面内部通信；TLS 证书验证维持开启。

## 三、桌面 Code 必须找到真正运行的程序

排查中最容易遗漏的是：Claude 主应用与桌面 Code 的执行文件不在同一个目录。

主应用在 /Applications/Claude.app；桌面 Code 会把版本下载到用户的 Library/Application Support/Claude/claude-code 下。只保护主应用不能代表独立 Code 目录也受到保护。

本次为两处分别设置 LuLu 目录规则，阻止外部直连，并保留本机代理规则。终端 npm CLI 又使用单独的 Node 副本及入口，避免把整个系统共享 Node 一并封住。目录内测试程序实测外部 IPv4、IPv6 连接失败，代理连接成功。

本地回环连接仍能工作，因此这不是“只有 1082 端口才能访问”的隔离机制。外部浏览器、Flova 和其他目录里的子进程也不会自动继承这两条规则。

## 四、DNS 是这轮真正补上的一处遗漏

开始时，网页出口已经是美国，但 DNS 测试同时出现国内运营商和美国解析服务器。原因线索在 Shadowrocket：主 DNS 和备用 DNS 都写着 system，系统下层又连接本地路由器 DNS。

第一步将 system 换成公共 DNS 后，国内运营商消失，但仍混有香港解析节点。第二步把主备都改为经代理发送的 DoH：

```ini
dns-server = https://1.1.1.1/dns-query#proxy
fallback-dns-server = https://1.0.0.1/dns-query#proxy
```

再次运行浏览器检测，结果只剩美国波特兰 Cloudflare。关键不是“DNS 地址看起来在海外”，而是它的查询也确实经过预期路径。解析服务器的 IP 不必与网站看到的出口 IP 相同。

这项配置已加入电脑启动前检查。浏览器检测结果仍应单独复测，不能只凭配置字段正确就通过。

## 五、WebRTC 和国内分流分别检查

本轮 Chrome 的 WebRTC 页面显示 No Leak，没有返回公网或内网地址；WebRTC 功能本身仍然开启。我们没有安装额外插件或禁用全部实时通信功能。

Flova、Bilibili 继续按域名 DIRECT，Claude 第一方域名按仅含固定节点的 US-FIXED。这样国内服务可以保留国内访问体验，而模型连接使用固定美国出口。默认 DNS 走代理，Flova API、WorkBuddy 等国内服务另有国内 DNS 覆写；DNS 与业务流量分开配置。

检查网站只说明这次、这个浏览器的结果；手机 X App、桌面 Code 的真实会话仍需各自验收。

## 六、每天使用时执行一个短流程

以下原流程对应旧 Mac 的历史检查器，不能直接复制到新机器；新机器按[部署手册](另一台Mac部署.md)逐项配置，仓库脚本只核对一次出口，不会自动拦截启动。原流程是：先确认 LuLu 启用，再连接固定节点，核对规则、代理、DNS 和两个独立出口站。通过后再打开桌面 Code，选择本地会话。使用中保持节点和路由不变；确实需要改网络时，先结束相关会话和后台进程。

当前手机使用独立 Trojan 凭据；若使用历史 WireGuard 方案，则须独立 peer 与密钥。二维码包含连接秘密，只在自己的设备之间传递。电脑本轮 DNS 更新不会自动同步到手机，需要在手机配置里应用相同 DNS 段后再次测试。

这套方案的交付包括：教程对照、配置步骤、恢复方法、检测脚本与验收记录。它管理的是连接稳定性和意外直连，不替代真实账号会话的功能验收。
