# 给另一台 Mac 上的助手的交接说明

可把以下内容作为部署请求。执行者必须先克隆仓库并验证公开包，再按完整清单逐项推进：

> 请先运行 `python3 scripts/validate_public_bundle.py`，扫描失败立即停止。随后以 `docs/第二台Mac完整执行清单.md` 为主流程，参考 `docs/另一台Mac部署.md` 和 `docs/操作手册.md`，在这台 Mac 部署固定美国出口与国内服务分流，并建立、验证 Claude 桌面及桌面 Claude Code 的应用直连限制。先读取本机现状，备份后只合并必要字段；禁止用仓库模板覆盖整份 Shadowrocket、Claude 或 LuLu 配置。使用我通过 Git 之外的安全本地渠道提供的现有 VPS 独立设备凭据；不能从仓库猜测秘密、复用另一台设备的身份或擅自购买资源。先用全局代理单独测试 Trojan/TCP 443/TLS 节点，确认两个出口站均返回预期静态 IPv4，再合并分流；VPS 的 `DIRECT,no-resolve` 规则必须位于代理规则之前。Claude 绑定唯一 US-FIXED 节点；Flova、B站、飞书、抖音、小红书、WorkBuddy 和微信开发者工具按仓库清单执行国内直连与最小 DNS 例外。保持严格 TLS，不得启用 `allowInsecure`，不得照抄旧机器路径、UUID、哈希或用户名。先做无账号故障注入，再验证真实 Claude Code 会话；不主动提交付费生成。逐项区分“已保存、已生效、已测试、未验收”。仓库没有运行中 IP 变化自动断流机制，不得声称已经具备；也没有通用 CLI 启动器，共享 Node 的终端 npm CLI 必须标为未保护，除非另行实现并验收。所有密码、节点 URI、二维码、SSH 私钥、真实公网 IP、邮箱、认证日志和设备信息都保存在 Git 仓库外。

如目标是 Windows、Linux、路由器或 iPhone，应先重新制定对应防火墙与客户端流程，不照搬 macOS LuLu 路径。
